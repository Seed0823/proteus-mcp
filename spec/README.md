# 电路清单（spec）

一份 JSON，描述「有哪些元件」和「谁跟谁连着」。它是图片和 Proteus 工程之间的中间层：
图片读出来的结果先落成清单，再由 `scripts/draw_spec.py` 照清单画图，
最后由 `scripts/netlist_diff.py` 把画出来的网表跟清单逐脚比对。

格式刻意做得笨——只写电气关系，不写坐标、不写走线。

## 结构

```json
{
  "meta": {"title": "4 位 ALU", "source": "assets/schematic.png"},
  "components": [
    {"ref": "U1", "part": "74LS181", "col": 2, "row": 0},
    {"ref": "SW0", "part": "SW-SPDT", "col": 0, "row": 0,
     "pins": {"NO": "VCC", "NC": "GND"}}
  ],
  "nets": [
    {"name": "A0", "pins": [["SW0", "COM"], ["U2", "D0"]]},
    {"name": "GND", "pins": [["U1", "$OE$"], ["LED0", "K"]]}
  ]
}
```

### components

| 字段 | 必填 | 说明 |
|---|---|---|
| `ref` | 是 | 位号，后面 `nets` 里引用的就是它。沿用原图的位号，比对时才好对得上 |
| `part` | 是 | 器件库里的精确名。`74LS181`、`74LS373`、`SW-SPDT`、`LED-RED` 这类，写错放不进去 |
| `value` | 否 | 74LS 系列不给就默认等于 `part`，给了能避免仿真报模型加载失败 |
| `col` / `row` | 否 | 摆位用：col 是第几列（0 最左），row 是同列第几个。不给就按 0 列堆 |
| `x` / `y` | 否 | 直接给坐标（thou，原点在图中央）。给了就忽略 col/row |
| `pins` | 否 | 固定电平的脚，如 `{"NO": "VCC", "NC": "GND"}`，会直接打网络标号 |

### nets

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 网名。`VCC` / `GND` / `VDD` / `VSS` 会一律用网络标号连，不实画线 |
| `pins` | 是 | `[["位号","引脚名"], ...]`，至少两个 |
| `style` | 否 | 写 `"label"` 表示这根网用两端同名标号连，不实画线（跨得远时省事） |

## 画的时候会发生什么

1. 按 `col` 分列摆件，同列从上往下排，间距 500 thou。
2. 元件 `pins` 里的固定电平和电源网先打标号——先打标号再布线，否则标号抢不到通道。
3. 其余网逐根调用 `route_nets`。一根一次，不能批量。
4. 哪根布不通（`routed: 0`），就退化成两端打同名标号。电气等价，只是图上没线。

## 比对判什么

`netlist_diff.py` 把清单和网表都看成「哪些引脚属于同一组」，然后查三类问题：

| 问题 | 意思 |
|---|---|
| 分家 | 清单说这几脚连着，网表里被拆成两段 |
| 短接 | 网表把两根本该分开的网粘成一根 |
| 没交代 | 图上接了、清单里没写的引脚（`--strict` 时算失败） |

第三类是这套方法的软肋：清单漏写一根线，图和清单会"一起错"，两边自然一致。
所以它默认只警告并列出名字，加 `--strict` 才算失败。读图的时候漏了什么，
从这里能看出来。
